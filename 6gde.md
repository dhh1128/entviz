- 2026-08-04T16:13Z Found 2026-08-04 by the entviz-rs port agent while reproducing the new v16 btc-segwit-testnet vector, and confirmed against the reference. src/entviz/characterize.py:213 sets q['network'] = 'mainnet' unconditionally inside the 'if type_name.startswith("BTC")' branch, because the parser types both bc1 and tb1 as 'BTC SegWit' and never distinguishes them. Verified: characterize('tb1qw508d6qejxtdg4y5r3zarvary0c5xw7kxpjzsx') returns qualifiers {'network': 'mainnet', 'variant': 'segwit'} and render_label gives 'BTC, tb1'. The mainnet address gives the same label modulo the prefix slot.

This is NOT just a metadata nit. _mods() emits the network slot only when it departs from mainnet (docs/spec-change-log.md v14: 'a blockchain testnet network (mainnet silent)'), so a testnet address is missing the loud marker the spec says it should carry. The reference is non-conformant to its own v14 rule, and it is the same confusability family v16 just addressed for the HRP: mainnet vs testnet over one payload. CashAddr gets this RIGHT (characterize.py:222 keys network off a bchtest prefix), which is what makes the BTC branch look like an oversight rather than a decision. Check Litecoin (characterize.py:225) and BTC legacy testnet (m.../n... prefixes) for the same hole while fixing.

COST, and why it was NOT fixed on the spot. The fix changes the rendered label for testnet values, which is spec-observable exactly as the v14/v15 label changes were, so it is a spec bump plus a corpus regeneration plus a re-pin in all four ports. It was cheapest at the moment of discovery (2026-08-04, when all four port commits were local and unpushed) and gets more expensive after the ports are pushed and released. It was deliberately deferred anyway because it is outside 'make the ports v16-compliant' and the maintainer was away; doing a second release-train pass unilaterally would have invalidated four freshly verified ports. See RELEASE-TRAIN.md for the sequencing this would need.

NOTE the v16 corpus SHIPS the wrong value: compliance/corpus/btc-segwit-testnet/model.json records network=mainnet, and all four ports now reproduce it to pass Tier A. Fixing the reference REQUIRES regenerating that golden.
